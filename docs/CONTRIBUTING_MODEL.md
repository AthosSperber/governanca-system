# Contribution Model

## Governance Basis

The repository evolves under constitutional authority and a stable protocol. Contributions are governed, traceable, and auditable. Change is accepted only when it is scoped, classified, and aligned with the governing documents.

## Sprint Alignment

Every change maps to a sprint. Sprints define the permitted scope of work and the review criteria. Changes that do not align with an active sprint are rejected as out of scope. Drive-by pull requests are rejected because they lack declared scope, traceability, and governance context.

## Contribution Classification

### Documentation Evolution

Documentation evolution is limited to documentation artifacts. It does not alter runtime behavior, protocol semantics, or domain logic.

### Implementation Evolution

Implementation evolution modifies code or execution behavior within constitutional bounds and sprint scope. It requires explicit scope and traceability.

### Constitutional Evolution

Constitutional evolution modifies the Constitution or its annexes. It follows the formal amendment process and must be explicitly justified and traceable.

## Review Expectations

Review focuses on scope clarity, classification accuracy, constitutional alignment, and sprint traceability. Changes without explicit alignment or without declared non-goals are considered out of scope.
